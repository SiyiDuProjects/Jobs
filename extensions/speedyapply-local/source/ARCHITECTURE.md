# Autofill runtime contracts

These implementation contracts are enforced by the adapter, writer, ownership and submission tests. Operational permissions and delivery boundaries stay in the repository AGENTS.md.

- **A missed control** appears in the snapshot's `unrecognized` list (question, reason, tag/role/class outline) and as a local reproduction case. Make it readable in its layer: a site's structure in `src/custom/platform-config.js` declarations, a widget as a registered component (`describe`/`facts`, `readOptions`, `choose`) in the `control-fields.js` registry; standard ARIA comboboxes already use the fallback. Never add site branches to the scanner; all page clicks/events go through `JobsPageActions`.
- **Every adapter** (all 30 in `source/content/adapters/`) runs each page/step as one `JobsAutomatic.advance({fill})`. Adapters provide structure actions and ordered `JobsFormPipeline.bind` declarations (`name/find/answer`, `answers`, `checked/replace`, `after`) only; they never write answers, read options or call a resolver (`tests/one-answerer.test.mjs` checks every adapter). Sign-in fills use `jobsFillAccount` outside a run; step buttons come from `jobsStepNavigation`. Inside the run each binding is written in page order, then every remaining empty node is resolved at most once, conditional fields settle/rescan, then evidence-checked supplemental answers, review and navigation. A run keeps one field ledger (`JobsFormPipeline.ledger`: state, decider, confirm, card); every answer (binding, rule, AI, review card) reaches a field only through `JobsFormPipeline.write` (claim → write → kept by the page → decide or abstain), and a failure changes only that field's record. Optional supplemental fields accept only a verified `write`; unsupported optional questions remain empty without a review card. A canonical node has one automatic decider per run (the layer whose value it holds); a second claim must diagnose and fail. A binding or rule that cannot match or keep its value abstains; an unresolved choice is passed with its actual options to the server. Filling defaults never establish personal facts. `JobsFormPipeline.answered(root)` provides all automatically decided nodes excluded from saved manual responses, including AI and remote writes. Option writes use `optionSpec` through the sole `chooseSpec -> chooseFrom` transaction. Waits are conditions (`JobsFormPipeline.settled`, bounded `JobsDOMWait.until`), never fixed delays; an unconfirmed upload returns a hold and does not navigate. A new ATS is added the same way.
- **Typed facts and option meanings.** `profile-answers.js` contains typed fact readers, formatters and option specifications. `answer-vocabulary.json` owns versioned canonical short labels and option concepts. `answer-resolver.js` resolves canonical labels and signature formatting; it does not classify free-form question prose or match keyword memories. Components open, search, list, click and read back without reading the Profile. Structure such as an `educationIndex` belongs to adapters and components.
- **Server decisions.** `answers.py` asks the model only to map public questions to the closed fields, computed predicates, default categories or draft intents in `answer_bindings.py`. Recognition never receives a Profile, prior answers or filled form values. `answer_values.py` computes from the pinned server Profile; precedence is Profile facts (including false), exact person-origin answers from the same company, enabled defaults, then blank. The cache stores only public mappings and links to the private corpus. It excludes option IDs and posting IDs; exact question shape, explanatory context, country, model and contract revision control reuse. Each executable proof binds the current exact field, option IDs, value and Profile version. Unknown/malformed/duplicate rows affect only their field. No second-model verifier, AI-notes citations, guessed fallback or topic whitelist exists. Cache-only requests need no key or provider call. Actual model batches consume the 60/hour budget, including cached open-draft intents. The task queue retains its independent transport limits.
- **Drafts and interruptions.** The shared protocol is `write`, `draft`, or `ask`. Drafts are restricted to recognized open motivation, preference and experience prose, using structured Profile data with AI notes removed. Required drafts in person mode are recorded in a tab/Profile/version/job-bound journal and reviewed together before submission; edits invalidate approval. Unverified suggestions never preselect or write card choices. Person edits use the sole write pipeline. Confirmation drains pending edits and acknowledges valid answers; whole-page validation blocks automatic navigation if any required or invalid field remains, while releasing native controls for manual repair. A cancelled operation never auto-resumes. Unknown optional answers remain blank.
- **Learning ownership.** Only explicit person-origin answers enter saved responses. Agent and page-tool operations never become person-origin through trusted browser events. Records retain full question, operator origin, time, company/country/job context and original scope. Unknown legacy origin is not promoted; keywords and appearance counts are compatibility data only, not an answer engine. Client-side saved records never override the current Profile locally.
- **Behavior tests** protect every adapter and component; the historical comparison with the original bundle was retired on 2026-09-24.
- **Private question corpus.** `corpus-content.js` captures inert form trees before continuation and on person corrections. It never awaits upload or writes to the page. `corpus-case.js` removes form values, selection state, credentials, file names and matching identity text; actual option/search observations stay in transient memory and upload only through the authenticated Profile boundary. Review pages are skipped. Background probes a fingerprint before upload; the server compresses only new questions, structures or search recordings and counts repeats. Corrections are unlabelled samples, never automatic gold answers. Independent labels and the existing predicate cache feed offline replay using the real scanner and evaluator with synthetic identities. Conflicting country mappings remain unresolved. The normal test/update suite runs the ignored local corpus when present; an absent corpus is an explicit skip. Replay does not establish successful site writes or real-page acceptance.

Each automatic run owns one AbortController. Its AbortSignal reaches the operation context; lifecycle changes, removal, manual navigation and source invalidation cancel the same signal. A cancelled signal cannot be reset by a later review or asynchronous response. Review pauses input listeners while the person intentionally edits, then validates the current operation before resuming.

New pure policy modules are ordinary ES modules and their unit tests import their exports directly. DOM integration fixtures use an isolated browser realm with explicit dependencies; their module loader must preserve the maintained module bodies and import bindings.

Typed-function fixtures freeze explicit type inputs to preserve formatter and option coverage. DOM fixtures mock the authenticated provider boundary; they do not establish model comprehension. Service tests independently verify recognition isolation, deterministic evaluation, protocol and rejection behavior. Real-provider and real-ATS acceptance remain separate.
