# 从故障记录到回归案例

## 使用者

重新加载扩展后，新打开的申请页面会在填写停于 `complete-required`、`complete-manually` 或 `site-error` 时，尝试保存未完成／校验错误字段的局部结构。打开扩展的「填写诊断」，也可点击「保存当前故障案例」。它只读取当前页面，不填写、点击、翻页或提交。页面关闭后，仍能从「已保存案例」导出之前留下的快照。

新故障默认未解决，后台重启后仍保留；只有在验证修复并标记已解决后才按 30 天清理。整份档案上限 10 MB，达到容量时明确拒绝新快照而不删除未解决案例。每轮最多 100 个未解决案例。单个快照最多 5 个字段、900 个节点、18 层、220 KB。达到上限会标注裁剪；超大快照会拒绝保存。岗位分组复用已有 ATS 身份规则，内部保存身份摘要和去除私密参数的岗位地址。不会向服务器的普通诊断接口上传 DOM。

## 维护者

在扩展项目目录执行：

```text
node scripts/repro-case.mjs inspect <导出的案例.json>
node scripts/repro-case.mjs import <导出的案例.json> <英文案例名>
npm test
```

`inspect` 使用现有共享组件读取器，还原控件类型、组件、必填性、是否有值、校验状态和完成原因。与现场记录不一致时返回失败，先检查遗漏的 DOM、裁剪、样式或网站行为；不能把不完整的快照当成已经复现。

`import` 只接收能还原上述观察状态的案例，写入 `tests/fixtures/repro/`，不覆盖同名案例。测试库由 `tests/repro-library.test.mjs` 自动发现，普通 `npm test` 就会运行。当前两个示例由虚构页面通过实际捕获与导入流程产生：Greenhouse 搜索文字不等于已选学校；Workday 排他性 checkbox 组是一个单选问题。

导入后保护的是「能否准确读到当时的故障状态」，不是「故障已经修好」。修复时应围绕这个案例增加操作与期望结果。如果共享读取器本身有错，保留现场观察，在明确复现之后审阅更新回归预期，不可直接刷新所有基线。原有 React 控件、异步候选和明确输入输出的行为测试继续使用。

## 保留与缺失的信息

- 保留局部 DOM、相关已打开弹层、开放 Shadow DOM、技术类名与自动化属性、ARIA 关系、已选状态、原生校验失败状态、构建编号、答案来源／决策原因和有序事件。原生校验失败用固定的测试校验错误重现，不保留个人值或原校验内容。
- 填写值、题目文字与普通 ID 替换为虚构内容；仅保留必填标记、排他选择提示等通用识别线索。密码／验证码节点被排除，页面地址只保留来源域名。技术属性仍用于定位，所以案例仍属于私有项目诊断资料。
- 不记录网站脚本、框架事件处理器、网络回复、样式表、未打开的候选或 closed Shadow DOM。尚未被扫描器发现的题目、外部校验汇总等，也可能无法从这个字段快照复现。
- 离线重放不执行 ATS 路由、AI 请求或提交代码；不证明真实网站的填入／持久化／提交已通过。涉及异步搜索、失焦清空和站点验证的故障，仍需结合已有事件日志和真实页面或专门行为测试。

## 实现归属

| 入口                                   | 职责                                             |
| -------------------------------------- | ------------------------------------------------ |
| `src/custom/repro-case.js`             | 有边界的结构捕获、虚构值替换、案例校验与离线装载 |
| `src/custom/repro-background.js`       | 私有本地保存、申请分组、去重、容量限制           |
| `src/custom/diagnostics.js`            | 使用原扫描字段与时间线，在故障停止时捕获         |
| `src/custom/diagnostics-background.js` | 定向读取选中页面，校验当前文档／会话             |
| `src/custom/diagnostics-ui.js`         | 保存和导出入口                                   |
| `scripts/repro-runner.mjs`             | 离线加载真正的共享读取器并比较状态               |
| `scripts/repro-case.mjs`               | 检查、导入；不自动覆盖回归预期                   |

案例按 runId 关联脱敏历史，通过带单调版本的 caseRetention 将未解决状态同步到服务器。人工保留标记独立，浏览器不能取消它。不要为复现案例增加一套生产填写器。
