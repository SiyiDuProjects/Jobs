# 从事件和题库页面到回归

现场只保留两种记录：

1. **事件日志**：每道题的决定、答案来源、写入/读回结果和状态变化。个人值转换为同一次运行内可比较的虚构标记；不保存 DOM、页面文字或整页状态快照。事件以序号和确认回执保证可追踪，断连时保留未确认记录。
2. **题库页面**：去掉填写值、密码和附件信息的惰性结构，以及实际观察到的选项/搜索结果。普通采集与故障采集共用格式、存储和去重。失败是该页面上的标记，关联运行、文档和字段；标记解决不删除题库页面。新客户端每次运行的每个页面只有一条结局：列出插件没有自己完成的每道题及其账本结局（谁定的、被谁接手、为什么留下），页面结束前持续更新，未确认时按页面重发；`get_page_outcomes` 在页面关掉后读取。旧客户端按阶段写入的多条标记保留为历史数据。

“填写记录”可读取当前页面的临时状态、导出事件日志，或将当前页面标记失败并导出题库页面。读取不填写、不翻页、不刷新、不提交。题库没有确认接收时不报告保存成功。

## 回放与验收

`npm run corpus:test` 是扫描器/本地规则的快速检查。`scripts/corpus-flow.mjs` 执行实际共享链路：扫描、本地规则、待补答准备、包含 `formDocument` 的请求、写入与读回。动态选项使用原录制边界；没有录制的搜索结果明确报告缺口，不编造选项。

服务端 `deploy/corpus_flow_replay.py` 连接该回放进程；`deploy/compare_answer_flows.py` 对比两套引擎的真实请求。比较工具使用明确授权的数据库只读副本和私有输出，调用真实模型需要对应费用授权；普通测试使用合成 Profile 与固定响应，不调用真实模型。回放代码指纹覆盖 `source`、`src/custom`、测试装载器和 corpus 脚本。

题目、说明或选项已被旧版脱敏破坏的快照排除出验收，不能猜测恢复。模型录制是输入，不是正确答案标签。回放覆盖快照中观察到的控件和共享流水线，不证明真实站点接受、附件上传、导航或提交。

## 历史兼容

运行包不再启用 `repro-background` 或 `repro-case`。`scripts/repro-case.mjs`、`scripts/repro-runner.mjs` 及旧格式解析器仅用于读取历史导出和保留既有回归夹具，不再采集或另存现场页面。服务器沿用原读取工具/上传 URL 以兼容旧客户端，把旧字段清单投影为逐题状态事件；新记录的 `snapshots` 仅保留空数组协议占位。既有未解决记录和人工保留标记不因改名而丢失。
