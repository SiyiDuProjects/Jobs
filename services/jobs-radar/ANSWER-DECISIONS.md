# Answer decision protocol v2 — candidate, integration pending

The authenticated field-answer request pins the server Profile id and revision. The existing generator returns an answer plus exact Profile-path or verbatim note citations and a closed meaning. A single additional verification request checks the actual question, full options, answer and necessary resolved citations. Both provider calls use `store: false`; verification has no retry. The user authorized this additional call. A model check is fallible and does not establish formal semantic correctness; synthetic tests verify protocol handling, not a live model's interpretation of every audit question.

The server resolves citations itself and checks the topic's allowed paths, value shape and exact-date precision. The verifier returns only `write`, `draft`, `missing_fact` or `new_commitment` and closed meaning enums. Unavailable or malformed checks become `control_failure`; missing facts never retain a proposed value. Exact dates can cite one relevant education record without requiring every record to contain the same date. `calendar.today` is computed by the server in the extension's IANA time zone; it cannot establish a historical personal date.

A write/draft proof binds Profile id/revision, complete field/options, value, vocabulary version and an opaque evidence id. The background binds it to the exact request; the writer rejects missing or altered proofs before filling. Existing values, cancellation, ATS commit/readback, conditional rescans and the navigation latch remain in the shared pipeline. Empty search controls accept only a verified factual query, then search and choose an equivalent real option. A failed optional-only batch leaves optional fields empty; required failures retain the retry path.

Canonical short labels and structural adapter bindings retain typed answer functions. Free-form question classification, keyword Saved Response scoring, stopword extraction and local legal entailment regexes have been removed. The public meaning cache contains only closed enum values and is keyed by complete field structure, supplied job context, rule/vocabulary version and model. It contains no personal answers or quotations. The canonical vocabulary also generates the frontend degree/language catalogs.

In person mode, verified required subjective drafts are kept in a session-only checklist across application steps. Intermediate steps may continue; final review displays one checklist. Approval applies to its exact revision, and edits invalidate approval. In agent mode, the shared field review surface remains the agent's self-review interface. Draft storage verifies the document, current job, Profile version and connection before and after reads, and clears on tab close or connection change. Automatic answers, including AI and remote writes, cannot be learned as the person's own facts.
