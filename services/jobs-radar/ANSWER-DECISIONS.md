# Answer decision protocol v2 — integration pending

The field-answer request remains one existing provider request. Its schema adds exact Profile-path citations, verbatim note quotations and a closed topic classification. The server checks source existence, local topic/value support, scope and precision, then returns `write`, `draft` or `ask`. A write proof binds the Profile id/revision, complete field/options, answer value, vocabulary version and opaque evidence id. The extension background verifies those bindings; the content writer also checks the current field and preserves rule-level missing-fact holds. Old or mismatched proofs cannot remove confirmation.

The public meaning cache includes question, description, field type, options, job context, rule/vocabulary versions and model. It stores only enum classifications, never answers, Profile values or quotations. Review may show necessary citations, while the new diagnostic path records only controlled reason codes and opaque proof ids.

Local checks cover direct scalar facts, country-specific eligibility, separate current/future sponsorship, exact dates, degree and language categories and narrowly parsed explicit non-compete statements. Existence alone does not prove semantic support. Arbitrary notes, compound legal/status questions, new commitments and derived factual narratives still need broader verification. This branch is an integration candidate, not the completed answer-layer replacement. Do not deploy it or remove the existing classifiers until those cases are covered.

Automatic approval review rejected adding a second provider request for semantic verification. The pending user question proposes at most one additional request per batch, containing the questions, candidate answers and necessary cited facts, using the existing OpenAI service with storage disabled. No such request is implemented or sent. The pending decision must be resolved before implementing that transport.

The shared vocabulary and the independent signature, option-matching and review-conditional fixes have been integrated separately. Existing saved-answer scope remains unchanged; unknown legacy provenance is never promoted. Remote control remains until an authorized real application validates the page surface end to end. No live application, production release, push or personal-data migration is part of this candidate's local test evidence.
